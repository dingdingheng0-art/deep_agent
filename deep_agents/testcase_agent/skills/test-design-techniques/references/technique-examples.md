# 用例设计方法示例集

本文是 test-design-techniques 技能的配套示例库，需要时阅读。

## 示例 1：等价类 + 边界值（手机号+验证码登录）

需求：手机号 11 位数字，1 开头；验证码 6 位数字，有效期 5 分钟。

**等价类划分**：

| 输入 | 有效等价类 | 无效等价类 |
|---|---|---|
| 手机号 | ① 1 开头 11 位数字 | ② 非 1 开头 ③ 少于 11 位 ④ 多于 11 位 ⑤ 含非数字 ⑥ 为空 |
| 验证码 | ⑦ 6 位数字且未过期 | ⑧ 6 位但错误 ⑨ 非 6 位 ⑩ 已过期 ⑪ 为空 |

**边界值**：手机号长度 10 / **11** / 12；验证码长度 5 / **6** / 7；有效期第 4 分 59 秒 / **5 分 00 秒** / 5 分 01 秒。

**用例编排**：有效类 ①+⑦ 合并为一条正常用例；无效类 ②–⑥、⑧–⑪ 各自单独成条（防止错误掩盖：若一条用例同时填错手机号和错验证码，无法判断系统校验了哪一个）。

## 示例 2：判定表（会员折扣）

需求：黄金会员打 8 折；白银会员满 200 打 9 折；非会员无折扣；所有会员生日当天额外减 10 元。

**条件桩**：C1 黄金会员 / C2 白银会员 / C3 订单金额≥200 / C4 生日当天
**动作桩**：A1 8 折 / A2 9 折 / A3 减 10 元

| 规则 | R1 | R2 | R3 | R4 | R5 | R6 |
|---|---|---|---|---|---|---|
| C1 黄金 | T | T | – | – | F | F |
| C2 白银 | F | F | T | T | F | F |
| C3 ≥200 | – | – | T | F | – | – |
| C4 生日 | T | F | T | F | T | F |
| A1 8折 | ✓ | ✓ | | | | |
| A2 9折 | | | ✓ | | | |
| A3 减10 | ✓ | | ✓ | | | |

合并规则：R1 中 C3 无关（黄金不看出身金额），C1=T 覆盖金额任意 → 裁掉冗余列。每条剩余规则 → 一条用例，测试数据写明等级、金额、是否生日三个具体值。

## 示例 3：场景法（电商下单）

**基本流**：浏览商品 → 加入购物车 → 结算 → 选地址 → 提交订单 → 支付成功 → 生成订单

**备选流**：
- B1 购物车为空时点击结算 → 提示不可结算
- B2 未选择地址提交 → 阻断并提示
- B3 库存不足 → 提交失败提示
- B4 支付超时/取消 → 订单状态=待支付
- B5 支付失败重试 → 幂等，不重复扣款

**场景 → 用例**：
1. 基本流（P0）
2. 基本流 + B1（P1）
3. 基本流 + B2（P1）
4. 基本流 + B3（P1）
5. 基本流 + B4（P0，涉及订单状态与资金）
6. 基本流 + B5（P0，幂等性）

每条场景用例的步骤覆盖该场景流经的每个页面动作，预期结果写终态 + 关键中间反馈（如 B4 需验证订单列表状态为"待支付"且可继续支付）。

## 示例 4：状态迁移（订单状态机）

状态：待支付 → 已支付 → 已发货 → 已完成；待支付 → 已取消。

**合法迁移用例**：每条边一条（前置条件写初始状态，如"存在一笔待支付订单 O123"）。
**非法迁移用例**（验证被拒绝）：已取消 → 支付；已发货 → 取消；已完成 → 退款（若需求不支持）。预期写"操作被拒绝，提示 XXX，状态保持为 已取消"。

## 示例 5：错误推测补给包

对任何输入型/交易型功能，默认过一遍：

- 重复提交：连点两次提交按钮 → 只生成一条数据
- 浏览器回退后重新提交 → 幂等或明确提示
- 并发：两个标签页同时操作同一数据 → 最终状态一致
- 金额精度：0.01、999999999.99、负数、三位小数
- 特殊字符：`' " <script>alert(1)</script>` emoji `null` 字符串
- 时区：跨 0 点的日期边界、服务器与客户端时区不一致
