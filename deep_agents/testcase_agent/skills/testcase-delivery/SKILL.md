# 测试用例交付导出规范

定稿与导出阶段的质量门禁与参数构造规范。

## 交付前质量门禁（全部通过才允许导出）

- [ ] 评审结论为"通过"，或所有"必须修改"项已在终稿逐条落实（对照 `/review/review.md` 的修订核对清单）；
- [ ] 终稿已写入 `/exports/testcases.md`，且与 `/testcases/testcases.md` 的修订版一致；
- [ ] Markdown 表格列名与顺序严格为：用例编号 | 所属模块 | 用例标题 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 优先级 | 用例类型 | 设计方法；
- [ ] 用例编号唯一、优先级只取 P0/P1/P2。

## export_excel 参数构造

`testcases` 为 list[dict]，**逐行**从 Markdown 表格转换，字段映射：

| 表格列 | dict 字段 | 转换要点 |
|---|---|---|
| 用例编号 | case_id | 原样 |
| 所属模块 | module | 原样 |
| 用例标题 | title | 原样 |
| 前置条件 | precondition | 原样 |
| 测试数据 | test_data | 原样 |
| 操作步骤 | steps | `<br>` 分隔 → 转成字符串列表（工具会自动编号换行） |
| 预期结果 | expected_result | 同上，多预期转列表 |
| 优先级 | priority | 只取 P0/P1/P2 |
| 用例类型 | case_type | 原样 |
| 设计方法 | design_method | 原样 |

要点：
- **不得删减或改写内容**——Excel 必须与 Markdown 终稿逐字一致（仅格式转换）；
- 表格中转义的管道符 `\|` 还原为 `|`；
- 一次调用传全量用例，不要分批。

## export_xmind 参数构造

- `title`：被测系统/需求名称（取自需求文档标题）；
- `tree` 层级固定三层：**模块 → 功能点 → 测试点**，结构为
  `{"title": "模块名", "children": [{"title": "功能点", "children": [{"title": "[正常] 测试点…"}]}]}`；
- 测试点节点保留 `[正常]/[边界]/[异常]` 前缀标签；
- 数据来源是 `/analysis/test_points.md`（测试点视角），不是用例表——导图用于需求覆盖脑图，与 Excel 互补。

## 汇总报告模板

最终回复用户时按此结构（中文，简洁）：

```
## ✅ 测试用例已生成完毕

**规模**：共 N 条用例，覆盖 M 个模块 / K 个功能点（测试点覆盖率 100%）
**优先级**：P0 x 条 / P1 y 条 / P2 z 条
**设计方法**：等价类 a · 边界值 b · 场景法 c · 判定表 d · 状态迁移 e · 错误推测 f
**评审结论**：<通过 / 修订 N 处后通过>

**交付物**：
- 📄 Markdown 终稿：<链接>
- 📊 Excel 用例表：<链接>
- 🧠 测试点思维导图：<链接>
```

三个下载链接必须来自 export 工具返回值，禁止手写拼接。
